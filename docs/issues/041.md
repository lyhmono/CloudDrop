# ISSUE-041: 认证限流存在并发流水绕过

- **状态**: done
- **优先级**: P1
- **区域**: src/room.ts

## 问题

handleAuth 是「先读计数 → await crypto.subtle.digest → 最后写回」，中间没有串行化。
Durable Object 在 await 处会让出事件循环，同一房间内并发到达的多条 auth 消息会各自
读到相同的旧计数、各自跑完整验证，再分别写回 —— per-connection 的 authAttempts、
全局 authFailures 都会丢失更新（互相覆盖）。例如同一连接把 attempts=0 的状态同时用于
多条并发尝试，「每连接 5 次」的上限形同虚设。网段桶计数虽有 blockConcurrencyWhile，
但读取阈值的判断在锁外，同样被绕过。

## 修复方案

把「检查限流 → 验证 → 写回计数」整体放进 blockConcurrencyWhile 串行区，排队期间
重新 deserializeAttachment 读取最新计数，而不是用消息到达时的快照。digest 是纯内存
计算，串行化没有性能代价。incrementBucketAuthFailures 内部的 blockConcurrencyWhile
随之移除（该 API 不可嵌套），由外层统一保护。ws.close/send 补 try 包裹防止串行区内
抛错影响后续。
