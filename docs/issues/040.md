# ISSUE-040: 跨站 WebSocket 无 Origin 校验，恶意网页可枚举/劫持用户自动房间

- **状态**: done
- **优先级**: P1
- **区域**: src/index.ts, tests/smoke-ci.mjs

## 问题

WebSocket 升级不受同源策略约束：/ws 与 /api/room/check-password 全程不校验 Origin。
任意恶意网页可以在「访问过 CloudDrop 的受害者」浏览器里直接 new WebSocket 连入——
请求源 IP 就是受害者本人，恰好命中他按 IP/24（或 /64）自动分配的房间。脚本因此能：
静默 join 枚举房间内设备名/浏览器信息、向成员注入信令，甚至按房间内待满 3 秒即可
设密的规则抢先把房间加密、把原成员踢出（close 4001）。
文件传输本身仍受确认流程 + E2EE 保护，但房间隐私边界与所有权已被打穿。

## 修复方案

Worker 层新增 isTrustedOrigin：浏览器发起的升级必带 Origin，非同源直接 403；
非浏览器客户端（curl/ws 库）不带 Origin、无法伪造，保持放行以兼容 API 调用与冒烟测试。
/ws 与 /api/room/check-password 两个入口统一挂门禁。smoke 增加回归断言：
跨站 Origin 升级必须得到 403，无 Origin CLI 连接必须仍能 join。
