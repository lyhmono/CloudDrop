# ISSUE-042: 设密者断线会跳过对旧成员的撤权

- **状态**: done
- **优先级**: P2
- **区域**: src/room.ts

## 问题

handleSetPasswordViaWs 在持久化密码后先执行未包裹 try 的 `ws.send(set-password-result)`，
之后才是 room-locked 广播与关闭其他成员的循环。若设密者连接恰好在 `await storage.put`
期间断开，send 抛出会跳过整个撤权循环 —— 密码已生效，但旧成员 attachment 仍是
`isAuthenticated: true`，可以继续使用已加密房间的信令。

## 修复方案

撤权先于回执：广播 room-locked、关闭旧成员都执行完后，最后用 safeSend 给设密者发确认帧。
回执失败不影响已经完成的安全状态。
