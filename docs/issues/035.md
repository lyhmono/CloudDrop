# ISSUE-035: 早到的 ICE 候选被过早冲刷丢弃

- **状态**: done
- **优先级**: P1
- **区域**: public/js/webrtc.js, tests/webrtc-negotiation.test.mjs

## 问题

线上控制台可见 "Failed to add buffered candidate: ... The remote description was null"。createConnection 里刚 new RTCPeerConnection 就调用 _flushPendingCandidates，此刻 remoteDescription 必然为 null，addIceCandidate 必定失败；而该函数在失败后无条件 pendingCandidates.delete(peerId)，于是这批候选被直接丢弃。

触发窗口是 prewarmConnection 那 300-600ms 的延迟：对端在窗口内发出的早期候选（通常是 host 候选）到达本端时本端还没有 pc，只能进缓冲，随后被这次过早的冲刷吃掉。host 候选恰恰是 LAN 直连最有价值的一批。

## 修复方案

未就绪（remoteDescription 为 null 或无 type）时保留缓冲并 debugLog，等 handleOffer / handleAnswer 设置完 remoteDescription 后再冲刷；单个候选被拒不再连坐其余候选（无效候选没有重试价值，仍按失败丢弃）。

测试补两个用例：未就绪时不得调用 addIceCandidate 且缓冲必须原样保留、就绪后冲刷成功并清空缓冲。用旧实现跑这两个用例会失败。
