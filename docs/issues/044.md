# ISSUE-044: /api/room/check-password 无 IP 限流，可批量探测房间码

- **状态**: done
- **优先级**: P2
- **区域**: src/index.ts

## 问题

该端点每个合法请求都会激活对应房间的 Durable Object（读一次 storage），却完全没有
按 IP 的速率限制。攻击者可对不同房间码高频请求，既做房间存在性探测，也把 DO 初始化
与存储读取成本放大成 DoS 面。/api/ice-servers 早就有 isIceServersRateLimited，这里一直漏配。

## 修复方案

把原先写死只服务 ice-servers 的限流器泛化为 isIpRateLimited(store, ip, maxPerIp) +
独立窗口常量，ice-servers（10/分）与 check-password（30/分）各用一张 Map 记账，
超限返回 429；沿用原有的「size>500 顺带清理过期条目」防 Map 无限增长。
（注：wrangler dev 本地不保持模块级状态，限流只在生产 Workers 生效——本地验证时需临时降阈值才看得到 429。）
