# ISSUE-039: ICE 列表里有一个不可路由的 STUN 死条目

- **状态**: done
- **优先级**: P3
- **区域**: public/js/config.js, src/index.ts

## 问题

stun:stun.syncthing.net:3478 同时出现在服务端默认 ICE 列表与客户端 FALLBACK_ICE_SERVERS 里，但该域名解析到 192.0.2.42 —— RFC 5737 的文档保留网段，不可路由，永远拿不到 srflx 候选。它只会白占客户端 STUN 健康检查的一个并发位并刷 ICE 报错。

（顺带核实：stun.miwifi.com 实测能正常返回 STUN binding 响应，之前控制台那条 701 host lookup 报错是测试环境设了代理导致的假象，不应据此删掉这个中国友好的服务器。）

## 修复方案

从两处列表移除 stun.syncthing.net，并加注释写明原因，避免以后被重新加回来。
