# ISSUE-037: URL 房间号格式非法时静默换房

- **状态**: done
- **优先级**: P2
- **区域**: public/js/app.js

## 问题

init() 直接把 ?room= 参数大写后当房间号用，不校验格式；而服务端 handleWebSocket 用 /^[a-zA-Z0-9]{6}$/ 校验，非法值会被它回落到"按 IP 分配"的房间。于是用户手输一个位数不对的房间号（例如 7 位）时，会被静默带进另一个房间，界面上没有任何提示（/api/room/check-password 也会先返回 400）。

## 修复方案

客户端用 ROOM.CODE_PATTERN 校验 URL 参数，非法则提示 room.invalidCode 并按自动分配处理（roomCode 置 null，不再把非法值带进 /ws），同时用 history.replaceState 把废参数从地址栏摘掉，避免刷新时重复提示、也避免把无效链接分享出去。

实测：`?room=BADCODE`（7 位）打开后地址栏参数被清除、显示自动分配的 6 位房间号、控制台无报错；`?room=GOOD12` 仍正常进入指定房间。
